## 🎯 Актуальность

Выездные инженерные службы ежедневно обрабатывают десятки заявок, распределённых по городу. При ручном планировании маршрутов сложно одновременно учитывать:

- время визита;
- квалификацию исполнителя;
- наличие транспорта и оборудования;
- появление срочных заявок в течение дня.

Из-за этого возникают лишние переносы, опоздания и неравномерная загрузка сотрудников. Необходим сервис, который автоматически формирует оптимальный план работ и умеет оперативно перестраивать маршруты при изменении условий.

&nbsp;
## 🧩 Описание задачи

Разработайте программный сервис с веб-интерфейсом, который:

1. Распределяет заявки между инженерами по квалификации и доступности;
2. Учитывает временные окна посещения объектов; проверяет наличие транспорта и необходимого оборудования;
3. Строит маршруты с минимизацией времени в пути и нарушений SLA;
4. Автоматически перепланирует день при поступлении новой заявки;
5. Визуализирует результат на карте и показывает причины выбора маршрута.

Допускается использование алгоритмов маршрутизации (**VRP/VRPTW**), методов оптимизации, ML/AI-подходов или агентных систем — выбор технологии остаётся за командой.

## Правила назначения и оперативного перепланирования

### До начала рабочего дня

План можно полностью перестраивать. Заявки допустимо переносить между
инженерами без штрафа за изменение ещё не начавшегося плана.

### Когда работы уже начались

Каждый задействованный инженер увеличивает `used_engineers_penalty`, поэтому
решатель старается не вызывать дополнительную бригаду. Сам по себе этот штраф
не является запретом: если ограничения или большая выгода требуют другого
решения, OR-Tools может задействовать нового инженера.

При перепланировании уже выполненные, отменённые, выполняемые и находящиеся в
пути заявки переносить нельзя. Для остальных заявок учитывается стоимость
изменения действующего плана.

### Обычная заявка после условных 14:00

Для вручную созданной обычной заявки действует дополнительное правило:

- новый план может использовать только инженеров, которые уже находятся на
  линии;
- ранее незадействованного инженера вызывать из дома нельзя;
- если расчёт требует такого инженера, результат отклоняется;
- frontend показывает причину отклонения;
- новая заявка остаётся в статусе `NOT_SENT` — «Не назначена».

Условные 14:00 считаются наступившими, если хотя бы одна заявка с окном
`14:00–16:00` или более поздним уже выполняется либо выполнена.

### Авария после 14:00

Авария считается форс-мажором. После 14:00 она может:

- вызвать ранее незадействованного инженера;
- переназначить ещё не начатые заявки;
- изменить оставшуюся часть маршрутов.

Увеличение числа инженеров и изменения плана по-прежнему учитываются в
objective, но запрет на вызов нового инженера для аварии не действует. Уже
выполненные, отменённые, выполняемые и находящиеся в пути заявки остаются
зафиксированными.
