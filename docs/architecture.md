# Архитектура BeeRouting

## Краткая схема решения

```text
Интерфейс (Vue 3, Vuetify, MapLibre)
              |
              v
API v2 (Django REST Framework)
              |
              v
Сервисный слой и адаптер сценария
              |
              v
Алгоритм планирования
(Baseline / OR-Tools / ICO-DE / Timefold)
              |
              v
Данные сценария и результаты
(SQLite, JSON/CSV, матрицы OSRM)
```

Интерфейс загружает состояние выбранной территории через `/api/v2/`, запускает
расчёт и отображает маршруты, назначения и причины, по которым заявки остались
нераспределёнными. Django API отвечает за HTTP-контракт, хранение состояния и
вызов сервисного слоя; бизнес-логика не размещается во views и serializers.

Сервисный слой преобразует сохранённый сценарий в независимые от Django
domain-модели `OptimizationProblem`. Решатель получает инженеров, заявки и
готовые матрицы времени и расстояния, а возвращает `OptimizationResult`.
Результат сохраняется в SQLite и передаётся интерфейсу. Геометрию дорог и
матрицы для реального расчёта предоставляет OSRM; воспроизводимые тесты могут
использовать детерминированный coordinate provider.

Подробное описание алгоритмов, целевой функции, метрик, hard constraints и
soft constraints приведено в [документации по оптимизации](optimization.md).
Состав и происхождение входных файлов описаны в [документации по
данным](data.md), HTTP-контракт — в [описании API v2](api-v2.md).
