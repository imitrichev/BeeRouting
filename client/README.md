# BeeRouting — Frontend

Веб-клиент для планирования и оптимизации маршрутов инженеров. Он показывает
карту района, заявки, маршруты и показатели распределения, а также
поддерживает ручное и автоматическое перепланирование.

## Стек

- **Vue 3** (`<script setup>`, Composition API) + **TypeScript**
- **Vite** — сборка и dev-сервер
- **Pinia** — управление состоянием
- **Vuetify 3** — UI-компоненты, темы (светлая/тёмная)
- **MapLibre GL** — карта и маршруты
- **Sass (SCSS)** — стили

## Требования

- **Node.js** `>= 20.x` (рекомендуется LTS)
- **npm** `>= 10.x` (или `pnpm`/`yarn` — по вкусу, команды ниже для npm)
- Запущенный сервер API (по умолчанию `http://127.0.0.1:8000`)

## Установка

```bash
# 1. Клонировать репозиторий
git clone <repo-url>
cd <repo-folder>/client

# 2. Установить зависимости
npm install
```

## Переменные окружения

Создайте **вручную** в папке client/ файл `.env` со следующим содержимым:

```dotenv
VITE_API_URL='http://127.0.0.1:8000'
```

> Все переменные, используемые на клиенте, должны начинаться с `VITE_`.
> Значение `VITE_API_URL` подставляется в `API_URL`
> (`src/utils/consts.ts`) и используется HTTP-клиентом
> (`src/utils/requests.ts`) как базовый адрес.

При необходимости можно создать отдельные файлы для разных режимов:

- `.env.local` — локальные переопределения, не попадают в git;
- `.env.development` — только для `npm run dev`;
- `.env.production` — только для `npm run build`.

## Запуск в режиме разработки

```bash
npm run dev
```

По умолчанию приложение поднимется на [http://localhost:5173](http://localhost:5173).

Убедитесь, что сервер доступен по адресу из `VITE_API_URL`
(`http://127.0.0.1:8000`) и разрешает CORS-запросы с
`http://localhost:5173`.

## Сборка для продакшена

```bash
npm run build
```

Результат сборки — в каталоге `dist/`. Его можно раздавать любым статическим сервером (nginx, Caddy и т.п.).

Предпросмотр собранного бандла:

```bash
npm run preview
```

## Как это работает

1. При подключении `App.vue` предварительно загружает справочники территорий,
   районов, приоритетов, навыков, нормативов времени и типов транспорта через
   `useSelectorsStore`.
2. Выбор территории в `ControlRow` устанавливает `districtCode` и автоматически
   запускает загрузку данных района через
   `useDistrictDataStore.loadDistrictData`.
3. Кнопка «Назначить заявки» открывает `OptimizationDialog` и запускает
   оптимизацию. После успешного ответа хранилище обновляет
   `districtData.result`; в интерфейсе появляются показатели, маршруты,
   неназначенные заявки и столбец действий.
4. Кнопка «Перепланирование» открывает `ReplanDialog`, где можно выбрать одно
   из событий: недоступность инженера, отмену заявки или аварийную заявку.
   Результат отображается в `ReplanInfoDialog`.
5. Ручное переназначение доступно из таблиц заявок и маршрутов через
   `ReasignmentDialog`: сначала открывается предварительный просмотр, затем —
   подтверждение.

## Темы

По умолчанию используется **тёмная** тема. Переключатель светлой и тёмной тем
находится в шапке (`AppHeader`). Выбранная тема не сохраняется между сеансами.

## Возможные проблемы

- **Пустой экран или ошибки сети в консоли** — проверьте, что `.env` создан и
  `VITE_API_URL` указывает на работающий сервер.
- **CORS-ошибки** — убедитесь, что сервер разрешает источник запросов
  `http://localhost:5173` (или используемый вами порт разработки).
- **Карта не отображается** — для тайлов используется публичный сервер
  OpenStreetMap (`tile.openstreetmap.org`). Проверьте доступ в интернет.
- **`Cannot find module '@/...'`** — проверьте псевдонимы путей в
  `vite.config.ts` и `tsconfig.json`; при необходимости перезапустите сервер
  разработки.
